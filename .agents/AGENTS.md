# Персональная агентная операционная система (Agentic OS Workflow)

Настоящие правила определяют методологию работы ИИ-агентов (Antigravity / Antigravity IDE) в данном проекте на основе подхода единого источника контекста в Obsidian.

## 1. Архитектура знаний и контекст (Obsidian Vault)

Единым источником истины, памяти и контекста для разработки является локальное хранилище в `Obsidian/Vault/`:

- `Obsidian/Vault/context/` — Стандарты разработки, роль, правила FSD 3.0, стек технологий, гайдлайны кода и работы с Figma.
- `Obsidian/Vault/projects/` — Архитектура текущего проекта (`crm-app-bypass`), схемы API, структуры данных, требования к модулям.
- `Obsidian/Vault/resources/` — Дизайн-токены, спецификации Figma, шаблоны компонентов, UI-киты.
- `Obsidian/Vault/wiki/` — База знаний по методу Карпатова (атомарные статьи, перекрёстные ссылки `[[note]]`, структурированные требования из ТЗ и Figma).
- `Obsidian/Vault/daily/` — Дневники прогресса, отслеживание задач (TODO/Done), отчёты по спринтам и изменениям.
- `Obsidian/Vault/00 - Index (MOC).md` — Главный индекс хранилища (Map of Content).

## 2. Принципы взаимодействия ИИ-агента

1. **Контекстно-ориентированный подход (Context-First / Model-Agnostic)**:
   - Перед выработкой архитектурных решений, генерацией компонентов или внесением изменений агент обязался обращаться к базе знаний в `Obsidian/Vault/context/` и `Obsidian/Vault/projects/`.
   - Запрещено галлюцинировать по поводу стилей, структуры или бизнес-логики: всё сверяется со спецификациями FSD 3.0 и Figma-токенами из `resources/`.

3. **Ведение базы знаний по методу Карпатова (Wiki LLM)**:
   - При появлении новых требований, спецификаций или бизнес-задач агент структурирует их в атомарные заметки в `Obsidian/Vault/wiki/` с использованием Markdown-ссылок `[[topic]]`.

4. **Дневники и отслеживание задач (Daily Tracking)**:
   - В ходе выполнения крупных этапов работ агент ведет/обновляет текущий daily-файл в `Obsidian/Vault/daily/YYYY-MM-DD.md`.
